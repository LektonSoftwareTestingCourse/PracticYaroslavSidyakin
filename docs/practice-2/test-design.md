### Card Management Service

| ID | Требование | Источник |
|:---:|---|---|
| REQ-CMS-01 | `GET /health` возвращает 200 и число карт в базе | tz/05 п. 1 |

| REQ-CMS-03 | При создании `expiryDate` = текущая дата + 3 года в формате MMYY | tz/05 п. 2 |
| REQ-CMS-04 | Созданная карта получает статус `ACTIVE` | tz/05 п. 2 |

| REQ-CMS-07 | `PATCH /api/cards/{pan}` частично обновляет статус, лимиты и баланс | tz/05 п. 2 |

| REQ-CMS-14 | Сгенерированный PAN проходит проверку по алгоритму Луна | tz/05 п. 4 |
| REQ-CMS-15 | `POST /api/cards/{pan}/reserve` уменьшает `availableBalance` на сумму и возвращает 200 | tz/05 п. 5 |
| REQ-CMS-16 | Статус `INACTIVE` присваивается только при генерации (3 %) и не совпадает по смыслу с `DELETED` | tz/05 п. 2 |

## Классы эквивалентности

### Статус карты (вход авторизации)

| ID | Класс | Представитель | Ожидаемая обработка |
|:---:|---|---|---|
| EC-01 | Активная карта | `ACTIVE` | проверки продолжаются |
| EC-02 | Неактивная карта | `INACTIVE` | DECLINED, `CARD_INACTIVE` |
| EC-03 | Заблокированная карта | `BLOCKED` | DECLINED, `CARD_BLOCKED` |
| EC-04 | Просроченная карта | `EXPIRED` | DECLINED, код 54 |
| EC-05 | Удалённая карта | `DELETED` | карта недоступна, авторизация отклоняется как по отсутствующей карте |
| EC-06 | Карта отсутствует | PAN не существует в базе | DECLINED, код 14 |

`DELETED` не входит в перечень статусов ТЗ для авторизации, но достижим через
`DELETE /api/cards/{pan}`, поэтому вынесен в отдельный класс.

## Попарное тестирование (PICT)

### Модель авторизации

Модель: [`pict/model-authorize.txt`](pict/model-authorize.txt), seed:
[`pict/seed-authorize.txt`](pict/seed-authorize.txt), набор:
[`pict/pairwise-authorize.tsv`](pict/pairwise-authorize.tsv) — 27 комбинаций из
1944 при полном переборе.

| Параметр | Значения | Классы |
|---|---|---|
| `CmsState` | `UP`, `DOWN` | EC-45, EC-46 |
| `CardStatus` | `ACTIVE`, `INACTIVE`, `BLOCKED`, `EXPIRED`, `DELETED`, `ABSENT` | EC-01 … EC-06 |
| `ExpiryState` | `FUTURE`, `CURRENT_MONTH`, `PAST` | EC-16 … EC-18 |
| `AmountVsBalance` | `LESS`, `EQUAL`, `GREATER` | EC-07 … EC-09 |
| `AmountVsDaily` | `LESS`, `EQUAL`, `GREATER` | EC-10 … EC-12 |
| `MonthlyHeadroom` | `ENOUGH`, `EXACT`, `EXCEEDED` | EC-13 … EC-15 |
| `BinLookupState` | `UP`, `DOWN` | EC-47, EC-48 |

Ограничения модели:

| Ограничение | Смысл |
|---|---|
| `CmsState = DOWN` фиксирует все карточные параметры в нейтральные значения | при недоступном Card Management карта не читается, её атрибуты ненаблюдаемы |
| `CardStatus IN {ABSENT, DELETED}` фиксирует атрибуты карты | у отсутствующей карты нет ни срока, ни баланса |
| `CardStatus = EXPIRED` требует `ExpiryState = PAST` | иначе данные противоречивы: статус просрочки при действующем сроке |
| `CardStatus IN {INACTIVE, BLOCKED}` требует `ExpiryState = FUTURE` | чтобы причина отказа была однозначной |
| `MonthlyHeadroom = EXCEEDED` исключает `AmountVsDaily = GREATER` | иначе отказ всегда определяется дневным лимитом и месячный не проверяется |

## Расхождения ТЗ и реализации

Найдено чтением кода, без запуска стенда — дефекты-кандидаты до
воспроизведения на стенде.

| ID | Расхождение | Ожидание по ТЗ | Факт по коду | Влияние | Связанные кейсы |
|:---:|---|---|---|---|---|
| D-01 | Порядок проверок: баланс проверяется раньше лимитов | лимиты — шаги 4–5, баланс — шаг 6 (tz/04 п. 2) | `AuthServiceImpl.authorize`: сначала сравнение с `availableBalance`, затем `checkAndUpdateLimits` | при одновременном превышении лимита и нехватке средств возвращается 51 вместо 61 | TC-AUTH-27 |
| D-02 | Код недоступности зависимости | `responseCode = 05`, причина `ISSUER_TIMEOUT` (tz/04 п. 5) | `DeclineOutcome.SERVICE_UNAVAILABLE` → код `96`, причина `SERVICE_UNAVAILABLE` | внешние потребители не отличают таймаут эмитента от системной ошибки | TC-AUTH-35 |
| D-03 | Повторные попытки Bin Lookup | до двух повторов при 5xx (tz/04 п. 2) | `BinLookupClient.getIssuerId` перехватывает любое исключение и сразу возвращает пустой результат | однократный сбой внешнего сервиса не компенсируется | TC-AUTH-37 |
| D-04 | Ключ таблицы `limit_usage` | `card_id UUID REFERENCES cards(id)`, `UNIQUE(card_id, usage_date)` (tz/04 п. 4) | сущность `LimitUsage` хранит `pan`, уникальность по `(pan, usage_date)`, внешнего ключа нет | при повторном использовании PAN после удаления карты лимиты наследуются от прежней карты | TC-AUTH-24 |
| D-05 | Размер страницы по умолчанию | `limit = 50` (tz/05 п. 2) | в контроллере `@RequestParam(defaultValue = "10")`, а настроенное значение 50 недостижимо | клиент получает меньше данных, чем ожидает по спецификации | TC-CMS-15 |
| D-06 | Чтение удалённой карты | карта не возвращается, ожидается 404 (tz/05 п. 2) | маппер статуса бросает исключение на `DELETED` → ответ 400 | клиент не может отличить неверный запрос от удалённой карты | TC-CMS-31 |
